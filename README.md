# ahk-quick-keytouch

AutoHotkey を使って、ホームポジションから手をあまり動かさずに操作するためのショートカット集。

- 対象: Windows ＋ 日本語（JIS）配列キーボード（無変換・変換キーを使う）
- 動作環境: AutoHotkey **v2**（v2.0.31 で確認。v1 では動かない）

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `quick-keytouch.ahk` | 本体のスクリプト |
| `setup-startup.ps1` | ログオン時に自動で起動するよう登録・解除するスクリプト |
| `README.md` | この説明。「操作方法」の表はショートカット一覧の表示にも使う |

## セットアップ

1. [AutoHotkey](https://www.autohotkey.com/) v2 をインストールする（v1 と同時に入れておいてもよい）
2. このリポジトリを好きな場所に clone する（スクリプトはリポジトリ内のファイルをそのまま使う）
3. ログオン時に自動で起動するよう登録する（下のどちらか）

### 通常権限で起動する

スタートアップフォルダに、リポジトリ内の `quick-keytouch.ahk` へのショートカットを作る。

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-startup.ps1
```

### 管理者として起動する（推奨）

通常権限だと、タスクマネージャーや管理者のターミナルなど**管理者として動いているウィンドウにフォーカスがある間はショートカットが効かない**（Windows の仕様）。
管理者として起動すればこれを避けられる。

スタートアップフォルダのショートカットを「管理者として実行」にしても、Windows はログオン時の起動を止めてしまう。
そのため、タスクスケジューラに「ログオン時に最上位の特権で実行」するタスクとして登録する（UAC の確認も出ない）。

**管理者として開いた PowerShell** で実行する:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-startup.ps1 -Admin
```

二重起動を防ぐため、通常権限用のショートカットがあれば削除される。

タスクには AutoHotkey v2 の本体（`AutoHotkey\v2\AutoHotkey64.exe`）の場所が登録される。v1 用に登録していた場合や、AutoHotkey をインストールし直した場合は、このコマンドをもう一度実行して登録し直す。

> [!WARNING]
> 管理者で起動すると、`quick-keytouch.ahk` に書かれた内容は次のログオン時から管理者の権限で動く。
> このファイルは普通の権限でも書き換えられるので、知らない変更が入っていないか（`git diff` など）を確認してから使うこと。

登録されたタスクは「タスク スケジューラ」（`taskschd.msc`）のライブラリ直下に `ahk-quick-keytouch` という名前で表示される。そこから確認・無効化・削除もできる。

### 登録を解除する

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-startup.ps1 -Uninstall
```

タスクも削除する場合は管理者の PowerShell で実行する。

### スクリプトを更新したとき

登録先はリポジトリ内のファイルなので、`git pull` や編集のあとは再読み込み（`Ctrl + Alt + R` か、タスクトレイのアイコン → Reload Script）するだけでよい。

## 操作方法

基本は **無変換キー** を押しながら別のキーを押す。
ここの表は、機能メニューの「ショートカット一覧」にもそのまま表示される。

### カーソル移動・選択

| キー | 動作 |
| --- | --- |
| 無変換 ＋ `i` / `k` / `j` / `l` | ↑ / ↓ / ← / → |
| 無変換 ＋ Shift ＋ `i` / `k` / `j` / `l` | Shift+矢印（選択） |
| 無変換 ＋ Ctrl ＋ `i` / `k` / `j` / `l` | Ctrl+矢印（単語単位で移動） |
| 無変換 ＋ Shift ＋ Ctrl ＋ `i` / `k` / `j` / `l` | Shift+Ctrl+矢印（単語単位で選択） |
| 無変換 ＋ `;` | Home（Shift で選択、Ctrl で文書の先頭へ） |
| 無変換 ＋ `:` | End（Shift で選択、Ctrl で文書の末尾へ） |
| 無変換 ＋ `.` | PageUp（Shift で選択、Ctrl で前のタブへ） |
| 無変換 ＋ `/` | PageDown（Shift で選択、Ctrl で次のタブへ） |

## 補足

### ショートカットが急に効かなくなったとき

CPU が混んでいると、Windows がキー監視（キーボードの低レベルフック）の応答を待ちきれずに、黙って外してしまうことがある（既定では 300ms 以内に応答しないと時間切れになり、11 回目で外される）。外れたキー監視は自動では付け直されない。
そうならないように、スクリプトでは次のことをしている。

- プロセスの優先度を「高」にして、混んでいても応答が遅れにくくする
- キーを押すたびに本体へ判定を問い合わせる `#HotIf` をできるだけ使わない（テンキーモードは割り当てのオン・オフで切り替える）。残っている変換 ＋ Shift ＋ `t` の判定も、待ち時間を 50ms までにしている
- キー監視とは別の仕組み（Raw Input）でもキー入力を見ておき、「キーは押されているのにキー監視が何も見ていない」状態が続いたら、キー監視を自動で付け直す（付け直したときは通知が出る）

それでも効かなくなったら Ctrl ＋ Alt ＋ `R` で再読み込みする。
このキーは、キー監視が外れていても効く方法（Windows への登録）で登録してある。
キー監視が外れると Shift や Win が押しっぱなしの扱いのまま残ることがあるので、Shift や Win が付いた Ctrl ＋ Alt ＋ `R` でも反応するようにしてある。

### 機能メニューのアプリ

メモ帳・電卓・ターミナル（cmd）は、すでに開いていれば新しく開かずにそのウィンドウを前面に出す。
ターミナルは、タイトルが「コマンド プロンプト」の Windows Terminal のウィンドウ（cmd のタブを表示しているもの）があればそれを前面に出す。PowerShell のタブを表示しているウィンドウは対象にしない。
VS Code は、開いていても毎回新しいウィンドウを開く。
スクリプトを管理者で動かしていても、アプリは通常権限で起動する（通常権限で動いているエクスプローラーに起動してもらう）。

### Win+L（ロック）

Win+L は Windows が直接処理するため、そのままでは Win ＋ 無変換 ＋ `l` を押すとロックがかかってしまう。
そこでスクリプトの起動中は、レジストリ（`HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System` の `DisableLockWorkstation`）で Windows 側の Win+L を無効にし、代わりにスクリプトが Win+L でロックする。普段どおり Win+L でロックできる。

- スクリプトを普通に終了・再読み込みしたときは、自動で元に戻る
- タスクマネージャーなどで強制終了すると元に戻らず、Win+L と Ctrl+Alt+Del の「ロック」が使えないままになる。スクリプトを起動し直せば Win+L は使えるようになり、終了すれば元に戻る
- 起動中は Ctrl+Alt+Del の画面に「ロック」が表示されない

### ショートカットを変更したとき

`quick-keytouch.ahk` を変更したら、この README の「操作方法」の表も合わせて更新する。
ショートカット一覧はこの表を読み込んで表示しているので、表を更新すれば一覧にも反映される。
